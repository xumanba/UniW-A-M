# PAIR: Plug-in Adaptive Interface Router

PAIR picks one of the four action-producing interfaces (Joint-WAM, IDM-WAM,
Action-Centric-WAM, Action-Only-WAM) for every action chunk. The UniW(A)M
backbone stays frozen; the router is a small MLP stored outside the model
checkpoint. PAIR is opt-in: nothing in `train.py` or `infer.py` changes unless
you train a router and call it.

## Router inputs

For chunk `c` of a four-chunk window, the frozen backbone receives the same
request the selected interface would receive (the seed frame on chunk 0, the
nine frames of the preceding chunk afterwards), and PAIR reads:

| Input | Source |
| --- | --- |
| `video` | first `1 + 2c` latent frames through all DiT blocks with only the shared expert active, mean-pooled |
| `clip` | CLIP image tokens after the DiT image projection, mean-pooled |
| `state` | current state through the DiT state encoder |
| `text` | instruction tokens after the DiT text projection, mask-pooled |
| `position` | one-hot of `c` |

Each input is layer-normalized, concatenated and passed through a two-layer
MLP that outputs one logit per interface. The model code is in
[`pair_router.py`](../groot/vla/model/dreamzero/modules/pair_router.py).

## Training a router

Set `CKPT` to a complete UniW(A)M checkpoint and run from the checkout root.

```bash
CKPT=/path/to/complete_checkpoint
OUT=./outputs/pair

# 1. Sample windows and split them by episode (train/val/test).
python -m uniwam.pair.windows --data-root "$UNIWAM_DATA" \
  --output "$OUT/windows.json"

N=$(python -c "import json;print(json.load(open('$OUT/windows.json'))['num_windows'])")

# 2. Labels: per-chunk action error of all four interfaces on those windows.
torchrun --standalone --nproc_per_node=8 -m uniwam.inference.fourway \
  --data-root "$UNIWAM_DATA" --checkpoint "$CKPT" \
  --windows-json "$OUT/windows.json" --num-windows "$N" \
  --out-dir "$OUT/labels"

# 3. Router features from the frozen backbone.
torchrun --standalone --nproc_per_node=8 -m uniwam.pair.features \
  --data-root "$UNIWAM_DATA" --checkpoint "$CKPT" \
  --windows-json "$OUT/windows.json" --out-dir "$OUT/features"

# 4. Train several seeds (a small MLP; one GPU or the CPU is enough).
for seed in 0 1 2 3 4 5 6 7; do
  python -m uniwam.pair.train --seed "$seed" \
    --features "$OUT/features/chunk_features.npz" \
    --labels "$OUT/labels/predictions.json" \
    --out-dir "$OUT/routers"
done

# 5. Score the seed ensemble on the test episodes.
python -m uniwam.pair.evaluate --routers "$OUT/routers" \
  --features "$OUT/features/chunk_features.npz" \
  --labels "$OUT/labels/predictions.json" --split test
```

Steps 2 and 3 run the full model and dominate the cost; step 2 runs every
interface on every chunk. Training targets are soft distributions over
interfaces built from the chunk errors; chunks where the best two interfaces
are within `--tie-eps` (relative) are assigned to the two single-pass action
interfaces, the cheapest choice when quality is tied. The validation split
selects the best epoch.

`uniwam.pair.evaluate` scores open-loop routing: every interface was
evaluated with recorded history, and the report compares the routed error with
each fixed interface and the per-chunk oracle.

## Deployment

```python
from uniwam.pair.gate import PAIRGate

gate = PAIRGate(model, "./outputs/pair/routers",
                exclude=("idm_lingbot_va",), chunk0_allowed=("idm_lingbot_va",))

task, probs = gate.route(batch, chunk_index)   # once per chunk boundary
if task != active_task:
    model.wam_episode_reset(task)              # new interface starts a fresh window
    active_task = task
```

`batch` is the request for the next chunk, built with
`uniwam.inference.episode.BatchBuilder`, and `chunk_index` is its position in
the active interface's four-chunk window (0 right after a switch). The gate
adds one observation-only backbone pass per chunk.

Options:

- `exclude` / `chunk0_allowed`: in closed loop, IDM-WAM on chunks 1 to 3
  consumes actions generated by whichever interface ran before it, which its
  open-loop labels do not reflect. Excluding it except on chunk 0 keeps it
  where it needs no action history.
- `joint_threshold`: fall back to Joint-WAM unless another interface wins with
  at least this probability (0 keeps the argmax, 1 always picks Joint-WAM).
- `probe_experts`: must match `--probe-experts` used for feature extraction.

Router checkpoints are tied to the backbone checkpoint and embodiment whose
features they were trained on; retrain them when either changes.
